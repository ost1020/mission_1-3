## 1. 실행 방법
* **실행 명령어:** `python main.py`
* **모드 선택:** 터미널 출력에 따라 `1` (사용자 입력) 또는 `2` (data.json 분석) 입력.
* **데이터:** `main.py`와 같은 경로에 `data.json` 파일이 위치해야 함.

## 2. 구현 요약
* **라벨 정규화:** `DataValidator.normalize_label()`을 통해 `+`, `cross` 등을 `Cross`로, `x`를 `X`로 변환하여 내부 판정 로직의 일관성을 확보함.
  * *확장 가이드:* 신규 라벨 추가 시 `normalize_label()` 분기 추가 $\rightarrow$ `data.json` 테스트 케이스 작성 $\rightarrow$ 예외 동작(FAIL) 확인 순으로 검증.
* **MAC 연산 구현:** `MACProcessor.calculate_mac()`에서 외부 라이브러리 없이 이중 `for` 루프를 순회하며 위치별 곱셈 및 누적 합산(`+=`) 수행.
  * *유사도 측정 원리:* 일치하는 픽셀(1과 1)이 만나는 위치에서만 양의 값(1)이 누적되므로, 총점이 클수록 입력 패턴과 필터 간의 기하학적 형태가 유사함을 의미함.
* **동점 처리 정책:** IEEE 754 부동소수점 연산의 미세 오차를 방어하기 위해 `abs(score_a - score_b) < 1e-9` (epsilon) 기반 비교 정책 적용.
  * *정책 설계 의도:* 모드 1(단일 테스트)에서는 사용자가 오차를 인지하도록 `판정 불가`를 명시하고, 모드 2(일괄 테스트)에서는 자동화된 엄격한 검증을 위해 `UNDECIDED`를 즉시 `FAIL`로 집계하도록 분리 설계함.
  * *Epsilon 튜닝:* $10^{-9}$은 $N=25$ 규모의 누적 오차를 방어하기에 충분하나, $N$이 수천 단위로 커지거나 시스템 정밀도가 낮아질 경우 $10^{-6}$ 수준으로 완화 조정이 필요함.

## 3. 결과 리포트
* **일괄 테스트 요약 통계:**
  * 총 테스트 케이스 중 다수의 정상 케이스가 정확히 일치하여 `PASS` 판정을 획득하였으며, 의도된 예외 및 동점 케이스에서만 정책에 따른 `FAIL`이 발생하여 방어 로직의 무결성이 검증됨.
* **FAIL 케이스 상세 원인 분석 (`size_13_1` 등):**
  * **발생 현상:** `size_13_1` 패턴에 대한 Cross와 X 필터의 MAC 연산 결과가 컴퓨터 내부 부동소수점 연산 특유의 미세한 반올림 오차로 인해 발생함.
  * **방어 로직 작동:** 두 점수의 차이가 허용오차 범위(`1e-9`) 내에 수렴하여 시스템이 논리적 오류를 방지하고자 `UNDECIDED`(판정 불가)로 분류하였으나, 기대값(`expected`)과 일치하지 않아 시스템 규칙에 따라 최종 `FAIL` 처리됨.
* **시간 복잡도 분석 ($O(N^2)$) 및 CPU vs NPU 병목 비교:**
  * MAC 연산은 $N \times N$ 크기의 2차원 리스트를 순회하기 위해 이중 루프를 사용하므로 시간 복잡도는 엄격한 $O(N^2)$을 가짐.
  * 성능 분석 측정 결과(10회 반복 평균), 패턴 크기가 증가함에 따라 메모리 역참조 및 산술 연산 횟수가 제곱 비례하여 기하급수적으로 증가함을 실측 증명함.
  * **CPU의 직렬 병목:** CPU 구조는 다수의 단순 반복 연산을 순차 처리하므로 메모리 포인터 추적(Memory Fetch) 과정에서 심각한 병목 현상이 발생함.
  * **NPU의 병렬 처리:** 반면 NPU는 수천 개의 MAC 연산 유닛(ALU)을 동시에 구동하여 데이터를 병렬 처리하므로 연산 부하를 상쇄함.
  * **소프트웨어 최적화 우선순위:** CPU 환경의 한계를 극복하기 위해 본 시뮬레이터에 적용된 1차원 평탄화(Flattening) 기법과 같이 메모리 접근 패턴을 단순화하는 최적화가 필수적임.
