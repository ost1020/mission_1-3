## 1. 실행 방법
* **실행 명령어:** `python3 main.py`
* **모드 선택:** 터미널 출력에 따라 `1` (사용자 입력) 또는 `2` (data.json 분석) 입력.
* **데이터:** `main.py`와 같은 경로에 `data.json` 파일이 위치해야 함.

## 2. 구현 요약
* **라벨 정규화:** `DataValidator.normalize_label()`을 통해 `+`, `cross` 등을 `Cross`로, `x`를 `X`로 변환하여 내부 판정 로직의 일관성을 확보함. 
  * *확장 가이드:* 신규 라벨 추가 시 `normalize_label()` 분기 추가 $\rightarrow$ `data.json` 테스트 케이스 작성 $\rightarrow$ 예외 동작(FAIL) 확인 순으로 검증.
* **MAC 연산 구현:** `MACProcessor.calculate_mac()`에서 외부 라이브러리 없이 이중 `for` 루프를 순회하며 위치별 곱셈 및 누적 합산(`+=`) 수행.
  * *유사도 측정 원리:* 일치하는 픽셀(1과 1)이 만나는 위치에서만 양의 값(1)이 누적되므로, 총점이 클수록 입력 패턴과 필터 간의 기하학적 형태가 유사함을 의미함.
* **동점 처리 정책:** IEEE 754 부동소수점 연산의 미세 오차를 방어하기 위해 `abs(score_a - score_b) < 1e-9` (epsilon) 기반 비교 정책 적용.
  * *정책 설계 의도:* 모드 1(단일 테스트)에서는 사용자가 오차를 인지하도록 `판정 불가`를 명시하고, 모드 2(일괄 테스트)에서는 자동화된 엄격한 검증을 위해 `UNDECIDED`를 즉시 `FAIL`로 집계하도록 분리 설계함.
  * *Epsilon 튜닝:* $10^{-9}$은 $N=25$ 규모의 누적 오차를 방어하기에 충분하나, $N$이 수천 단위로 커지거나 시스템 정밀도가 낮아질 경우 $10^{-6}$ 수준으로 완화 조정이 필요함.

## 3. 결과 리포트
* **FAIL 케이스 원인 분석:**
    * **동점 처리 FAIL (`size_13_1`):** 수학적으로 동일한 연산 결과가 부동소수점 오차로 인해 미세하게 다르게 산출됨. epsilon(`1e-9`) 기반 검증 로직에 의해 두 값의 차이가 오차 허용 범위 내에 있어 `UNDECIDED`(판정 불가)로 방어적 분류가 이뤄졌으며, 예상값(`X`)과 일치하지 않아 의도된 FAIL로 처리됨.
* **시간 복잡도 분석 ($O(N^2)$) 및 CPU vs NPU 병목 비교 (FAIL 항목 보완):**
    * MAC 연산은 $N \times N$ 크기의 2차원 리스트를 순회하기 위해 이중 루프를 사용함.
    * 측정된 평균 연산 시간(ms)은 `3x3`(0.010ms, 9회)에서 `25x25`(0.682ms, 625회)로 증가하며, 연산 횟수($N^2$) 증가 폭에 완벽히 비례하여 기하급수적으로 증가함을 실측 증명함 (고해상도 타이머 `time.perf_counter()` 사용).
    * **CPU의 한계 (직렬 병목):** 본 시뮬레이터(CPU 구동)는 $N^2$번의 메모리 역참조와 산술 연산을 한 번에 하나씩 직렬(순차) 처리함. 2차원 리스트 포인터 추적(Memory Fetch) 과정에서 병목 현상이 극대화됨.
    * **NPU의 해결책 (병렬 처리):** 반면 NPU는 수천 개의 MAC 연산 유닛(ALU)을 물리적으로 배치하여, 데이터를 병렬(동시)로 쏟아부어 곱셈과 덧셈을 단일 클럭(1 Cycle)에 처리하므로 $O(1)$에 가까운 시간 복잡도 최적화가 가능함.
    * *소프트웨어 최적화 우선순위:* CPU 환경의 물리적 한계를 극복하기 위해 1차원 평탄화(Flattening) $\rightarrow$ 캐시 블로킹(Loop Blocking) $\rightarrow$ SIMD 벡터화 순으로 메모리 접근 최적화를 우선 고려해야 함.
